## 1. PM 아키타입 (한국 시장)

| 아키타입 | 핵심 키워드 | 대표 역할 예시 |
|----------|------------|---------------|
| **Growth PM** | 그로스, 지표 중심, A/B 테스트, 퍼널 최적화 | 그로스 PM, 마케팅 PM, CRM PM |
| **Platform PM** | 플랫폼, 인프라, 개발자 경험, API | 플랫폼 PM, 인프라 PM, DevEx PM |
| **B2B PM** | 기업용 제품, SaaS, 엔터프라이즈 | B2B PM, SaaS PM, 솔루션 PM |
| **Consumer PM** | 소비자 제품, UX, 리텐션, 사용자 경험 | 서비스기획자, UX PM, 프로덕트 PM |
| **AI/Data PM** | AI 제품, 데이터 기반 의사결정, ML 파이프라인 | AI PM, 데이터 PM, ML Product Manager |

아키타입은 상호 배타적이지 않다. 하나의 공고가 복수 아키타입에 해당할 수 있으며, 주 아키타입과 부 아키타입을 구분하여 평가한다.

## 3. 스코어링 체계

- **스코어 범위**: 1.0 ~ 5.0 (소수점 첫째 자리까지)
- 각 차원별 1.0~5.0 점수를 매긴 후 가중 평균으로 종합 점수 산출

### 판정 기준

| 종합 점수 | 판정 | 의미 |
|-----------|------|------|
| **4.0 이상** | 🟢 적극 지원 | 경력, 도메인, 보상 모두 높은 적합도. 즉시 지원 권장 |
| **3.0 ~ 3.9** | 🟡 선택적 지원 | 일부 차원에서 갭 존재. 전략적 판단 필요 |
| **3.0 미만** | 🔴 비추천 | 적합도 낮음. 지원 시 시간 대비 효율 떨어짐 |

## 4. 한국 시장 규칙

### 연봉 데이터 소스
- **잡플래닛**: 기업 리뷰 및 연봉 정보 (WebSearch로 참고)
- **블라인드**: 직장인 커뮤니티 연봉 공유 (WebSearch로 참고)
- **크레딧잡**: 공시 기반 평균 연봉 데이터 (WebSearch로 참고)
- ⚠️ 직접 크롤링은 불가. WebSearch 도구를 통해 참고 자료로만 활용한다.

### 한국 기업 문화 고려사항
- **야근 문화**: 공고/리뷰에서 워라밸 언급 여부 확인. "유연근무", "자율출퇴근" 키워드 주목
- **수평적 조직문화**: "님 문화", "수평적", "애자일" 등 키워드로 조직문화 파악
- **의사결정 구조**: 탑다운 vs 바텀업, PM 권한 범위 확인
- **스톡옵션/RSU**: 스타트업의 경우 스톡옵션 조건 반드시 확인

### PM 직군 특화 용어 매핑
- **서비스기획자** = Product Manager (한국 전통 명칭)
- **PO** = Product Owner (스크럼 기반 조직에서 사용)
- **프로덕트 매니저** = Product Manager (외래어 표기)
- **기획자**, **전략기획** = 맥락에 따라 PM과 다를 수 있음. JD 상세 확인 필요

### 대기업 vs 스타트업 구분
| 구분 | 대기업 | 스타트업 |
|------|--------|---------|
| 연봉 체계 | 호봉제/연봉 테이블 | 협상 기반 |
| 의사결정 | 다단계 결재 | 빠른 의사결정 |
| PM 역할 | 범위 한정적, 전문화 | 넓은 범위, 멀티롤 |
| 성장 경로 | 체계적이지만 느림 | 빠르지만 불확실 |
| 복지 | 안정적, 체계적 | 유연하지만 가변적 |

## 5. 윤리 가드레일

1. **자동 제출 금지**: 절대로 지원서를 자동으로 제출하지 않는다. 모든 지원은 사용자가 직접 수행한다.
2. **경력/성과 조작 금지**: 이력서, 자기소개서, 포트폴리오의 내용을 허위로 작성하거나 과장하지 않는다.
3. **낮은 점수 공고 비추천**: 종합 점수 3.0 미만 공고에 대해 지원을 강력히 비추천한다. 사용자가 강행할 경우 리스크를 명확히 고지한다.
4. **cv.md 런타임 읽기**: 사용자 경력 정보는 반드시 `cv.md`에서 런타임에 읽어온다. 절대 하드코딩하지 않는다.
5. **개인정보 보호**: 사용자의 연락처, 주민번호 등 민감 정보를 로그에 남기거나 외부로 전송하지 않는다.

## 6. 데이터 파일 경로

```
career-ops/
├── cv.md                        # 이력서 (런타임 읽기 필수)
├── career-description.md        # 커리어 설명 및 방향성
├── config/
│   └── profile.yml              # 사용자 프로필 설정 (선호 아키타입, 연봉 범위 등)
├── data/
│   ├── applications.md          # 지원 현황 추적
│   ├── pipeline.md              # 파이프라인 관리 (관심 → 지원 → 면접 → 결과)
│   └── scan-history.tsv         # 공고 스캔 이력 (TSV 형식)
```

### 파일 용도 설명
- **cv.md**: 사용자의 최신 이력서. 모든 평가 시 이 파일을 읽어 경력 정보를 참조한다.
- **career-description.md**: 커리어 목표, 선호하는 역할, 관심 도메인 등 정성적 정보.
- **config/profile.yml**: 선호 아키타입, 희망 연봉 범위, 근무 형태 선호 등 정량적 설정.
- **data/applications.md**: 지원한 공고 목록과 현재 상태 추적.
- **data/pipeline.md**: 전체 취업 파이프라인 뷰 (관심 공고 → 지원 완료 → 면접 진행 → 최종 결과).
- **data/scan-history.tsv**: 스캔한 공고의 이력. 중복 스캔 방지 및 트렌드 분석용.
