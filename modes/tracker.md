# 지원 현황 추적 (tracker)

이 모드는 `data/applications.md`를 기반으로 전체 지원 현황을 보여줍니다.

## 사전 조건

- `data/applications.md`가 존재해야 합니다. 없으면 evaluate 모드를 먼저 실행하세요.
- `templates/states.yml`이 존재해야 합니다 (상태 정의).

## 실행 절차

1. `data/applications.md`를 읽어 파이프 구분 테이블을 파싱합니다.
2. 요청에 따라 현황 요약, 필터링, 상태 변경, 무결성 검사를 수행합니다.
3. 변경 사항이 있으면 `data/applications.md`를 업데이트합니다.
4. 결과를 화면에 출력합니다.

## 기능

### 1. 현황 요약

```
=== 지원 현황 요약 ===
전체: 47건
├── 평가완료: 23건 (48.9%)
├── 지원완료: 12건 (25.5%)
├── 회신: 2건 (4.3%)
├── 면접: 3건 (6.4%)
├── 오퍼: 0건
├── 불합격: 4건 (8.5%)
├── 포기: 2건 (4.3%)
└── 패스: 3건 (6.4%)

평균 점수: 3.72
Top 5 공고 (점수순):
  ★4.5 | 토스 | PM, 토스페이 결제 | 지원완료
  ★4.3 | 카카오 | Product Manager, 카카오톡 | 평가완료
  ★4.1 | 당근 | 서비스기획자 | 면접
  ★4.0 | 네이버 | PM, 네이버쇼핑 | 평가완료
  ★3.9 | 쿠팡 | Product Manager | 지원완료
```

### 2. 상태별 필터링

- `tracker all` — 전체 목록
- `tracker applied` — 지원완료 건만
- `tracker interview` — 면접 진행 중
- `tracker top` — 점수 4.0 이상

### 3. 상태 변경

```
tracker update [#번호] [새 상태]
예: tracker update #005 면접
```

상태 변경 시 `data/applications.md`를 업데이트합니다.
`templates/states.yml`에 정의된 상태만 사용 가능합니다.

### 4. 무결성 검사

트래커 데이터의 무결성을 검사합니다:
- 유효하지 않은 상태값 감지
- 보고서 링크가 존재하는지 확인
- 중복 항목 감지
- 점수 형식 검증 (1.0-5.0)

## 데이터 파일 형식

`data/applications.md`:

```markdown
# 지원 현황

| # | 기업 | 직무 | 점수 | 상태 | 날짜 | 보고서 | URL | 비고 |
|---|------|------|------|------|------|--------|-----|------|
| 001 | 카카오 | Product Manager, 카카오톡 | 4.3 | 평가완료 | 2026-04-07 | reports/001.md | https://... | Growth PM |
| 002 | 토스 | PM, 토스페이 결제 | 4.5 | 지원완료 | 2026-04-07 | reports/002.md | https://... | B2B PM |
```

## 출력

| 출력 | 설명 |
|------|------|
| (화면 출력) | 현황 요약, 필터링 결과, 무결성 검사 결과 |
| `data/applications.md` | 상태 변경 시 업데이트 |

## 윤리 규칙

- 상태 변경은 사용자가 직접 요청한 경우에만 수행합니다. 자동으로 상태를 변경하지 않습니다.
- `templates/states.yml`에 정의된 상태만 사용합니다. 임의의 상태를 만들지 않습니다.
- 무결성 검사에서 발견된 문제는 보고만 하고, 자동 수정하지 않습니다.
