# 원클릭 온보딩 (setup)

career-ops-kr을 처음 사용할 때 실행하는 대화형 온보딩 모드.
기존 이력서(PDF/Word/마크다운)를 투입하면 자동으로 cv.md, career-description.md, profile.yml을 생성합니다.

## 사전 조건

없음. 이 모드가 다른 모든 모드의 사전 조건을 만들어줍니다.

## 실행 절차

### Step 0: 모드 선택

먼저 사용자에게 온보딩 모드를 선택하게 합니다:

```
온보딩을 시작합니다! 예상 소요 시간을 선택해주세요.

A) ⚡ 빠른 설정 (3분) — 이력서만 등록하고 나머지는 기본값 사용
   → Step 1 + Step 3~4 기본값 자동 설정
B) 📋 전체 설정 (5~10분) — 경력기술서 스켈레톤까지 함께 생성
   → Step 1~5 전체 진행
```

빠른 설정(A) 선택 시: Step 1 완료 후 Step 2를 건너뛰고, Step 3은 기본값(Consumer PM, 대기업+스케일업, 하이브리드)으로 자동 설정합니다. 사용자는 나중에 `config/profile.yml`을 수정할 수 있습니다.

### Step 1: 이력서 투입

사용자에게 질문합니다:

```
이력서 파일이 있으신가요?
A) PDF 파일이 있어요
B) Word(.docx) 파일이 있어요
C) 마크다운(.md) 파일이 있어요
D) 파일은 없지만 직접 입력할게요
```

#### A) PDF 파일

1. 사용자에게 파일 경로를 요청합니다.
2. Read 도구로 PDF를 읽습니다.
3. **파싱 검증**: 추출된 텍스트가 정상인지 확인합니다.
   - 텍스트가 비어있거나 깨진 경우 → 파싱 실패 처리 (아래 참조)
   - 비밀번호 보호 PDF → "비밀번호가 설정된 PDF입니다. 해제 후 다시 시도하거나 D)직접 입력을 선택해주세요."
4. 정상이면 경력사항, 학력, 역량 등을 구조화합니다.
5. cv.md 초안을 생성하여 보여줍니다.
6. 사용자 확인: "이 내용이 맞나요? 수정할 부분이 있으면 말씀해주세요."
   - 수정 요청 → 해당 부분만 수정 후 다시 확인
   - 확인 완료 → cv.md로 저장

**파싱 실패 시:**
```
PDF 내용을 정상적으로 읽지 못했습니다.
A) 다른 파일 형식으로 시도 (Word, 마크다운)
B) 직접 입력으로 전환
```

#### B) Word(.docx) 파일

docx 스킬을 사용하여 읽고, PDF와 동일한 과정을 진행합니다.

#### C) 마크다운(.md) 파일

1. 파일 경로를 요청하여 Read 도구로 읽습니다.
2. `examples/cv-example.md` 형식과 비교하여 구조화가 필요하면 재구성합니다.
3. 그대로 사용 가능하면 cv.md로 복사합니다.

#### D) 직접 입력

대화형으로 경력 정보를 수집합니다:

```
1. "이름과 연락처를 알려주세요." (이름, 이메일, 전화번호)
2. "현재 직무와 총 경력 연수는?" (예: Product Manager, 5년)
3. "경력사항을 알려주세요. 가장 최근 회사부터."
   → 각 회사별: 회사명, 기간, 직무, 주요 성과 2-3개
4. "핵심 역량은?" (예: 데이터 분석, A/B 테스트, 사용자 리서치)
5. "학력은?" (대학, 전공, 졸업년도)
```

수집한 정보로 cv.md를 생성합니다.

### Step 1a: cv.md 검증

cv.md 저장 후 자동으로 아래 항목을 검증합니다:

1. **필수 섹션 존재 여부**: 이름/연락처, 경력사항, 학력, 핵심 역량 중 누락된 섹션이 있으면 사용자에게 보완을 요청합니다.
2. **경력 연속성**: 경력 기간에 설명되지 않은 공백(1년 이상)이 있으면 알립니다.
3. **정량 지표 유무**: 경력사항에 정량적 성과(숫자, %, 매출 등)가 하나도 없으면 "정량 지표를 추가하면 평가 품질이 높아집니다"라고 안내합니다.

```
✓ cv.md 검증 완료
  - 필수 섹션: 모두 존재
  - 경력 공백: 없음
  - 정량 지표: 3개 발견
```

검증 통과 후 다음 단계로 진행합니다.

### Step 1.5: 기존 파일 덮어쓰기 보호

cv.md가 이미 존재하는 경우:

```
cv.md가 이미 존재합니다.
A) 기존 파일을 백업하고 새로 생성 (cv.md.backup으로 저장)
B) 기존 파일 유지 (이 단계 건너뛰기)
C) 덮어쓰기
```

career-description.md, profile.yml에도 동일한 보호를 적용합니다.

### Step 2: 경력기술서 생성

cv.md를 기반으로 경력기술서 스켈레톤을 생성합니다.

PDF에서 STAR 형식의 상세 프로젝트 기술은 어렵습니다.
따라서 **스켈레톤 + 대화형 보완** 방식을 사용합니다:

1. cv.md에서 경력사항의 각 프로젝트를 추출합니다.
2. 프로젝트별 스켈레톤을 생성합니다:
   ```
   ## 프로젝트: {프로젝트명}
   - 기간: {기간}
   - 소속: {회사명}
   - 역할: {직무}

   ### 프로젝트 개요
   (TODO: 프로젝트 배경과 목표를 2-3문장으로 설명)

   ### 주요 성과
   - (TODO: 정량적 성과)
   - (TODO: 정성적 성과)

   ### 담당 업무
   1. (TODO: 구체적 업무)
   ```

3. 상위 2-3개 프로젝트에 대해 질문합니다:
   - "이 프로젝트에서 가장 큰 성과는 무엇이었나요? 숫자가 있으면 좋습니다."
   - "어떤 업무를 주로 담당하셨나요?"
4. 답변을 반영하여 스켈레톤을 채웁니다.
5. 나머지 프로젝트는 TODO로 남기고, 사용자가 나중에 채울 수 있도록 안내합니다.
6. career-description.md로 저장합니다.

### Step 3: 프로필 설정

사용자에게 질문합니다:

```
1. "어떤 유형의 PM 역할에 관심 있으신가요?" (복수 선택 가능)
   → Growth PM — 지표 개선, A/B 테스트, 퍼널 최적화 중심
   → Platform PM — 내부 플랫폼, API, 개발자 도구 중심
   → B2B PM — 기업 고객 대상 SaaS/솔루션 중심
   → Consumer PM — 일반 사용자 대상 앱/서비스 중심
   → AI/Data PM — AI 기능, 데이터 파이프라인, ML 모델 중심
   (잘 모르겠으면 "Consumer PM"을 선택하세요. 나중에 변경할 수 있습니다.)

2. "관심 있는 기업이 있나요?" (복수 선택 가능)
   → 카카오 / 토스 / 네이버 / 당근 / 쿠팡 / 기타 (직접 입력)

3. "희망 연봉 범위는?" (만원 단위)
   → 최소: ____만원

4. "선호하는 근무 형태는?"
   → 출근 / 하이브리드 / 리모트

5. "선호하는 기업 규모는?" (복수 선택 가능)
   → 스타트업 / 스케일업 / 대기업
```

답변을 기반으로 `config/profile.yml`을 생성합니다.
구조는 `config/profile.example.yml`을 따릅니다.

### Step 4: 포털 설정

`templates/portals.example.yml`을 `portals.yml`로 복사합니다.
Step 3에서 선택한 관심 기업에 맞게 포털 목록을 커스터마이즈합니다.

### Step 5: 첫 스캔 실행

```
온보딩이 완료되었습니다!

생성된 파일:
✓ cv.md — 이력서
✓ career-description.md — 경력기술서 (스켈레톤)
✓ config/profile.yml — 프로필 설정
✓ portals.yml — 포털 설정

첫 스캔을 실행할까요?
A) 네, 바로 스캔해주세요 → scan 모드 실행
B) 아니요, 나중에 할게요
```

## 출력

온보딩 완료 후 생성되는 파일 목록:

| 파일 | 설명 |
|------|------|
| `cv.md` | 이력서 (PDF에서 파싱 또는 직접 입력) |
| `career-description.md` | 경력기술서 (스켈레톤 + 일부 채움) |
| `config/profile.yml` | PM 아키타입, 연봉, 근무형태 등 설정 |
| `portals.yml` | 한국 기업 포털 설정 |

## 윤리 규칙

- PDF에서 파싱한 내용을 **있는 그대로** 사용합니다. 성과를 과장하거나 없는 경력을 추가하지 않습니다.
- 사용자가 직접 입력한 내용만 cv.md에 반영합니다.
- 파싱 결과가 불확실한 경우 사용자에게 반드시 확인합니다.
