# 경력기술서 자동 생성 (career-desc)

이 모드는 JD에 맞춤화된 한국식 경력기술서 PDF를 생성합니다.
한국 PM 채용에서 경력기술서는 이력서만큼 중요합니다.

## 경력기술서란?

경력기술서는 이력서의 경력사항을 **프로젝트 단위로 상세히 기술**한 문서입니다.
이력서가 "무엇을 했는가"라면, 경력기술서는 "어떻게 했고 어떤 결과를 냈는가"입니다.

## 사전 조건

- `career-description.md` — 사용자 경력기술서 원본
- `cv.md` — 이력서 (보조 참조)
- JD URL 또는 텍스트 — 타겟 공고

## 경력기술서 구조

각 프로젝트에 대해 아래 형식으로 작성합니다:

```
### 프로젝트명
- 기간: YYYY.MM - YYYY.MM (N개월)
- 소속: 회사명 / 팀명
- 역할: Product Manager
- 팀 규모: 개발자 N명, 디자이너 N명

#### 프로젝트 개요
프로젝트의 배경과 목표를 2-3문장으로 설명합니다.

#### 주요 성과
- [정량] 핵심 지표 개선 수치 (예: 전환율 15% → 23% 향상)
- [정량] 매출/MAU/리텐션 등 비즈니스 임팩트
- [정성] 프로세스 개선, 팀 역량 향상 등

#### 담당 업무
1. 사용자 리서치 및 문제 정의
2. PRD 작성 및 스펙 정의
3. 개발팀과 스프린트 기획 및 실행
4. A/B 테스트 설계 및 분석
5. 이해관계자 커뮤니케이션 및 의사결정

#### 사용 도구/방법론
Figma, Jira, Amplitude, SQL, A/B Testing, 스크럼
```

## 실행 절차

### 1. JD 분석

evaluate 모드와 동일하게 JD에서 핵심 키워드와 요구 역량을 추출합니다.

### 2. 프로젝트 선택 및 순서 결정

`career-description.md`에서:
1. JD 요구사항과 가장 관련성 높은 프로젝트를 상위 3-5개 선택
2. 관련성 순으로 재정렬 (시간순이 아닌 관련성순)
3. 각 프로젝트가 JD의 어떤 요구사항을 커버하는지 매핑

### 3. STAR 형식으로 재구성

각 프로젝트의 성과를 STAR 형식으로 재구성합니다:
- **S**(Situation): 프로젝트 배경과 문제 상황
- **T**(Task): 본인의 역할과 담당 범위
- **A**(Action): 구체적으로 수행한 업무
- **R**(Result): 정량적/정성적 성과

### 4. JD 키워드 자연스럽게 반영

- JD에서 추출한 키워드를 각 프로젝트 설명에 자연스럽게 녹여냅니다.
- 키워드를 억지로 넣지 않고, 기존 경험을 해당 키워드의 맥락에서 재서술합니다.
- 예: JD에 "데이터 기반 의사결정"이 있으면, 기존 A/B 테스트 경험을 그 맥락으로 서술.

### 5. PDF 생성

`templates/career-desc-template.html` 템플릿을 사용하여 HTML 렌더링 후 PDF 생성.

```bash
node generate-pdf.mjs --input /tmp/career-desc-rendered.html --output output/경력기술서_기업명_직무명.pdf
```

## 윤리 규칙

- `career-description.md`에 있는 경험만 사용합니다.
- 정량적 성과는 원본에 기재된 수치만 사용합니다.
- 경험을 "재구성"하는 것은 OK, "날조"는 절대 NO.
- 매번 `career-description.md`를 런타임에 읽습니다. 하드코딩 금지.

## 출력

1. PDF 파일: `output/경력기술서_{기업명}_{직무명}.pdf`
2. 콘솔 요약:
```
=== 경력기술서 PDF 생성 완료 ===
기업: 토스
직무: PM, 토스페이 결제
선택된 프로젝트: 4개 / 전체 7개
키워드 반영: 16/20개
파일: output/경력기술서_토스_PM토스페이결제.pdf
```
