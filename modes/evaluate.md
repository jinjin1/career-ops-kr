# career-ops-kr: 공고 평가 모드 (Evaluate)

단일 채용 공고를 PM/PO 관점에서 심층 평가하는 모드.
사용자가 채용 공고 URL 또는 JD 텍스트를 붙여넣으면 이 모드가 실행된다.

---

## 사전 준비

평가 시작 전 반드시 아래 파일을 읽는다:

1. **`cv.md`** — 사용자의 이력서 (경력, 학력, 기술 스택, 프로젝트)
2. **`career-description.md`** — 경력기술서 (프로젝트별 상세 성과, STAR 스토리)

두 파일은 프로젝트 루트에서 탐색한다.
파일이 없으면 사용자에게 경로를 요청한다.

---

## 입력 처리

1. URL이 주어지면 WebSearch 또는 browse 스킬로 JD 전문을 수집한다.
2. 텍스트가 직접 주어지면 그대로 파싱한다.
3. JD에서 다음을 추출한다:
   - 직무명, 소속 팀/조직
   - 자격 요건 (필수/우대)
   - 주요 업무
   - 근무 조건 (위치, 근무형태, 연봉 범위)
   - 기업명, 기업 규모/단계

---

## 평가 블록

### Block A — 역할 요약

| 항목 | 설명 |
|------|------|
| PM 아키타입 | Growth / Platform / B2B / Consumer / AI-Data 중 분류 |
| 도메인 | 핀테크, 커머스, 헬스케어, SaaS, 소셜 등 |
| 기능 영역 | 전략기획, 데이터분석, UX기획, 그로스, 파트너십 등 |
| 직급 | 주니어 (0-3년) / 미드 (3-6년) / 시니어 (6-10년) / 리드 (10년+) |
| 근무형태 | 출근 / 하이브리드 / 리모트 |
| 기업 규모 | 스타트업 (시드-시리즈A) / 스케일업 (시리즈B+) / 대기업 |

아키타입 분류 기준:
- **Growth**: 지표 중심, A/B 테스트, 퍼널 최적화, 리텐션
- **Platform**: API, 개발자 경험, 시스템 설계, 내부 도구
- **B2B**: 엔터프라이즈 세일즈 연동, 고객 요구사항 관리, SaaS
- **Consumer**: 사용자 경험, 소셜, 커머스, 콘텐츠
- **AI-Data**: ML 파이프라인, 데이터 프로덕트, AI 기능 기획

### Block B — 경력 매칭

JD의 **모든** 요구사항을 하나씩 나열하고, cv.md 및 career-description.md의 구체적 경험에 매핑한다.

#### 매핑 테이블

| # | JD 요구사항 | cv.md 매칭 경험 | 매칭 강도 |
|---|------------|----------------|----------|
| 1 | (요구사항) | (구체적 경험 또는 "해당 없음") | Strong / Partial / Gap |

#### 갭 분석

매칭 강도가 Gap 또는 Partial인 항목에 대해:

| 갭 항목 | 심각도 | 완화 전략 |
|---------|--------|----------|
| (항목) | Critical / Moderate / Minor | (구체적 완화 방법) |

심각도 기준:
- **Critical**: 필수 자격요건이며 관련 경험이 전무. 서류 통과 가능성에 직접적 영향.
- **Moderate**: 필수 자격요건이지만 유사 경험으로 브리징 가능. 또는 우대사항이지만 핵심 역량.
- **Minor**: 우대사항이며 없어도 큰 불이익 없음. 학습으로 충분히 보완 가능.

#### 매칭 비율

```
매칭 비율 = (Strong 항목 수 × 1.0 + Partial 항목 수 × 0.5) / 전체 요구사항 수 × 100
```

### Block C — 직급 전략

1. **직급 미스매칭 감지**
   - cv.md의 총 경력 연차와 JD 요구 경력 비교
   - 오버퀄(연차 초과 3년+) / 언더퀄(연차 부족 2년+) / 적정 판단

2. **오버퀄일 때 — "시니어를 어필하되 거짓말하지 않기" 전략**
   - 해당 직급에서 기대하는 임팩트 수준에 맞춰 성과를 리프레이밍
   - "리드 경험이 있지만 IC로서 깊이 있는 실행을 원한다" 내러티브
   - 연봉 기대치 조정 필요 여부

3. **언더퀄일 때 — "다운레벨 되었을 때" 플랜**
   - 부족한 경험을 보완하는 트랜스퍼러블 스킬 강조
   - "빠르게 성장할 수 있는 근거" 제시 (학습 속도, 성과 곡선)
   - 면접에서 경력 부족을 선제적으로 다루는 화법

### Block D — 보상 분석

WebSearch를 활용하여 다음 데이터를 수집한다:

1. **연봉 데이터 수집 소스**
   - 잡플래닛 (jobplanet.co.kr) — 해당 기업 연봉 정보
   - 블라인드 (blind.co.kr) — 해당 기업/직군 연봉 후기
   - 크레딧잡 (creditjob.co.kr) — 기업 평균 연봉
   - 원티드 인사이트 — PM 직군 연봉 통계

2. **PM 직군 연차별 연봉 범위**

   | 직급 | 연차 | 연봉 범위 (만원) |
   |------|------|-----------------|
   | 주니어 | 0-3년 | (수집 데이터) |
   | 미드 | 3-6년 | (수집 데이터) |
   | 시니어 | 6-10년 | (수집 데이터) |
   | 리드 | 10년+ | (수집 데이터) |

3. **해당 기업 복리후생**
   - 스톡옵션/RSU 여부
   - 성과급 구조
   - 복지 포인트, 자기계발비
   - 워라밸 관련 (유연근무, 재택, 연차 등)

데이터 수집 불가 시 "데이터 미확인"으로 표기하고, 업계 평균 범위를 대신 제시한다.

#### 강조할 프로젝트/성과 우선순위

JD 요구사항과의 관련도 기준으로 career-description.md의 프로젝트를 순위화한다.
상위 3개 프로젝트에 대해:
- 이 공고에서 강조해야 할 포인트
- 리프레이밍 방향 (같은 경험을 이 JD 맥락에 맞게 재구성)
- 정량 지표 중 활용할 것

### Block F — 면접 준비

#### PM 케이스 인터뷰 예상 질문 (3-5개)

해당 기업의 제품/서비스와 JD를 기반으로 출제될 가능성이 높은 케이스 질문:

1. (제품 개선 케이스)
2. (지표 설계 케이스)
3. (우선순위 판단 케이스)
4. (추정 문제 — 해당 도메인 관련)
5. (기술적 의사결정 케이스 — 해당 시)

각 질문에 대해 접근 프레임워크와 답변 방향을 간략히 제시한다.

#### STAR 형식 스토리 (6-10개)

career-description.md에서 추출하여 JD 요구사항에 매핑한다:

| # | JD 요구사항 | STAR 스토리 제목 | S (상황) | T (과제) | A (행동) | R (결과) |
|---|------------|-----------------|----------|----------|----------|----------|
| 1 | | | | | | |
| ... | | | | | | |

스토리 선택 기준:
- JD 필수 요건을 직접 증명하는 스토리 우선
- 정량적 성과가 포함된 스토리 우선
- 최근 경험 (3년 이내) 우선

#### 기업/제품 사전 조사 포인트

면접 전 반드시 조사해야 할 항목:
- 최근 6개월 제품 업데이트/출시 내역
- 경쟁사 대비 포지셔닝
- 최근 뉴스/투자/인수 이슈
- 주요 지표 (MAU, 매출, 성장률 등 공개 데이터)
- 면접관 LinkedIn 프로필 (이름이 알려진 경우)
- Glassdoor/잡플래닛 면접 후기

평가 결과는 아래 마크다운 구조로 출력한다:

## 종합 점수: X.X / 5.0 — [적극 지원 / 선택적 지원 / 비추천]

### 점수 산출 내역

| 차원 | 점수 (1-5) | 가중치 | 근거 (한 줄) |

## 종합 점수 산출 공식

각 블록에서 1.0-5.0 점수를 매기고, `_shared.md`의 10개 차원 가중치에 따라 가중 평균을 산출한다.

```
종합 점수 = Σ (차원별 점수 × 차원별 가중치)
         = (역할경력매칭 × 0.20) + (도메인적합성 × 0.15) + (직급매칭 × 0.15)
           + (보상연봉 × 0.10) + (성장기회 × 0.10) + (기업문화 × 0.10)
           + (제품복잡도 × 0.05) + (팀구조 × 0.05) + (기술스택 × 0.05) + (리모트 × 0.05)
```

각 차원은 1.0-5.0 스케일:

| 점수 | 의미 |
|------|------|
| 5.0 | 완벽한 매칭 |
| 4.0 | 높은 적합도, 사소한 갭만 존재 |
| 3.0 | 보통. 의미 있는 갭이 있지만 완화 가능 |
| 2.0 | 낮은 적합도. 상당한 갭 존재 |
| 1.0 | 매우 낮음. 거의 매칭되지 않음 |

**블록별 차원 매핑:**
- Block A (역할 요약) → 제품복잡도, 팀구조, 리모트 점수 산출
- Block B (경력 매칭) → 역할경력매칭, 도메인적합성, 기술스택 점수 산출
- Block C (직급 전략) → 직급매칭 점수 산출
- Block D (보상 분석) → 보상연봉, 성장기회 점수 산출
- Block E (맞춤화) → 참고 정보 (점수 산출에 직접 사용하지 않음)
- Block F (면접 준비) → 참고 정보 (점수 산출에 직접 사용하지 않음)

## 지원 권장 기준

| 종합 점수 | 판정 | 설명 |
|----------|------|------|
| 4.0-5.0 | 🟢 **적극 지원** | 매칭도가 높고 준비 가능. 즉시 맞춤화 진행. |
| 3.0-3.9 | 🟡 **선택적 지원** | 갭이 있지만 완화 가능. 전략적 맞춤화 필수. |
| 2.0-2.9 | 🟠 **신중 검토** | 의미 있는 갭 존재. 특별한 동기가 있을 때만 지원. |
| 1.0-1.9 | 🔴 **비추천** | 매칭도가 낮아 시간 투자 대비 효율이 떨어짐. |

비추천이라도 사용자가 지원을 원하면, 가장 효과적인 전략을 제시한다.
절대 "지원하지 마세요"라고 단정짓지 않는다.

## 실행 지침

1. 모든 평가는 **한국어**로 출력한다.
2. JD 원문의 표현을 최대한 인용하여 매핑의 근거를 명확히 한다.
3. cv.md에 없는 경험을 있다고 하지 않는다. 갭은 갭으로 인정하되 완화 전략을 제시한다.
4. Block D에서 WebSearch 실패 시 "데이터 미확인"으로 처리하고, 진행을 멈추지 않는다.
5. 평가 완료 후 결과를 `reports/` 디렉토리에 `{기업명}_{직무명}_{날짜}.md` 형식으로 저장한다.
6. 사용자가 추가 질문이나 수정을 요청하면 해당 블록만 재평가한다.
